## 1. 战斗基础：GCD、插技、动画锁定与范围机制

### 1.1 GCD（全局冷却）与基准复唱时间

FF14 的战斗节奏由 **GCD（Global Cooldown，全局冷却）** 驱动。绝大多数「战技（Weaponskill）」与「魔法（Spell）」共享同一个 GCD 计时器：一旦使用其中一个，其他 GCD 技能必须等待计时结束。

| 项目 | 数值 | 备注 | 可信度 |
|---|---|---|---|
| 标准 GCD 基准值 | **2.50 秒** | 绝大多数战斗职业在速度属性 = 基准值时的 GCD | ✅官方（技能提示显示 Recast 2.50s） |
| GCD 显示精度 | 0.01 秒 | 游戏内向下取整到百分之一秒 | ⚠️社区 |
| GCD 下限 | 约 1.50 秒 | 攻速上限由系统硬限制 | ❓不确定具体值 |
| 复唱时间（Recast）≠ GCD | 部分技能有自己的复唱时间 | 例如绘灵法师 Rainbow Drip 为 6.00s、黑魔 Black Comet 为 3.30s；它们**同样受咏唱速度缩短** | ⚠️社区（[JP Lodestone 实测](https://jp.finalfantasyxiv.com/lodestone/character/42324892/blog/5438925)） |

**关键概念**：FF14 中「速度」属性缩短的是**复唱时间本身**，而不是「GCD 计时器」。因此攻速收益对所有技能（GCD 技能、DoT、自动攻击）是**乘法叠加在各自基准复唱上**的。

### 1.2 技能速度 / 咏唱速度 → GCD 公式

> ⚠️ **以下公式为社区推导（Allagan Studies / The Balance 体系），非 Square Enix 官方公布。**
> 主要来源：[Allagan Studies 参数文档（中文转载）](https://ff14.17173.com/content/2021-05-03/20210513135838090.shtml)、[Flyxiv FFXIV Stat Theory (7.0)](https://junyeopn.github.io/blog/docs/ffxivtheory/)、[JP Lodestone 7.05 实测推导](https://jp.finalfantasyxiv.com/lodestone/character/42324892/blog/5438925)。

**速度函数（整数化形式）**：

```
f(速度) = ⌊ 130 × ( Speed − SUB ) / DIV ⌋ + 1000
```

**GCD 计算**：

```
GCD(秒) = ⌊ BaseRecast × 1000 / f(速度) × 100 ⌋ / 100
```

其中常数（⚠️社区推导）：

| 等级 | SUB（速度/暴击/直击/坚韧的零基准值） | MAIN（主属性 / 信念 / 信仰的零基准值） | DIV（等级除数） | 可信度 |
|---|---|---|---|---|
| Lv 70 | 292 | 292 | 900 | ⚠️（[JP Lodestone](https://jp.finalfantasyxiv.com/lodestone/character/42324892/blog/5438925)） |
| Lv 80 | 380 | 340 | 1300 | ⚠️另一体系给 DIV = 3300，❓存疑（见下方说明） |
| Lv 90 | 400 | 390 | 1900 | ⚠️ |
| **Lv 100（Dawntrail，当前）** | **420** | **440** | **2780** | ⚠️两个独立来源一致 |

> ❓ **不确定点（重要）**：Allagan Studies 第 3 版文档（ShB/Lv80）在副属性函数中给出的等级除数是 **3300**（`Level{80}{DIV} = 3300`），而 [JP Lodestone 的实测推导](https://jp.finalfantasyxiv.com/lodestone/character/42324892/blog/5438925)与 [Flyxiv](https://junyeopn.github.io/blog/docs/ffxivtheory/) 分别给出 Lv80 = 1300、Lv90 = 1900、Lv100 = 2780。这两套常数不能同时成立；**对于 Lv100 的推导任务，建议以 2780 / 420 / 440 为准**（两个独立来源互相印证），旧版本常数仅供参考。

**换算率（Lv 100）**——把「属性点数」换算成百分比收益，这是做数值规划时最有用的表：

| 副属性 | 换算率（Lv 100） | 每 1% 需要 | 说明 |
|---|---|---|---|
| 技能速度 / 咏唱速度 | 0.1% 速度 / 21.38 点 | ≈ 214 点 | 同时加快 GCD、DoT 跳伤、自动攻击 |
| 暴击 | 0.1% 暴击率 / 13.9 点 | ≈ 139 点 | 同一数值同时提升暴击率与暴击伤害 |
| 直击 | 0.1% 直击率 / 5.05 点 | ≈ 50.5 点 | 每点收益最「便宜」，但只提升命中率 |
| 信念 | 0.1% 伤害 / 19.86 点 | ≈ 199 点 | 线性、稳定 |
| 坚韧 | 0.1% 伤害 / 24.82 点；0.1% 减伤 / 13.9 点 | — | 仅防护职业有效 |

**计算示例（Lv 100，标准 GCD 2.50s）**⚠️社区推导：

| 技能速度 | f(速度) | GCD | 每轮 2 分钟 GCD 次数（近似） |
|---|---|---|---|
| 420（零基准） | 1000 | **2.50s** | 48 |
| 634 | 1010 | 2.47s | 48 |
| 848 | 1020 | 2.45s | 48 |
| 1062 | 1030 | 2.42s | 49 |
| 1276 | 1040 | 2.40s | 50 |
| 1704 | 1060 | 2.35s | 51 |
| 2138 | 1080 | 2.31s | 51 |
| 2560 | 1100 | 2.27s | 52 |

> 表格为按公式手算的近似值，实际取值受游戏内取整影响，**从事数值设计时请以公式为准、不要直接抄表**。

**速度的次要收益**：速度属性同时按同一比例提升 **DoT（持续伤害）每跳伤害** 与 **自动攻击伤害**（⚠️社区：`Auto/DoT Attack Increase = 100 + Speed Increase %`）。这就是为什么「攻速」在 FF14 中不是纯节奏属性，而是**实质 DPS 属性**。

### 1.3 oGCD（能力技）与插技 Weaving

| 术语 | 英文 | 说明 |
|---|---|---|
| GCD 技能 | Weaponskill / Spell | 占用 GCD，共享 2.5s 计时器 |
| oGCD / 能力技 | Ability | 不占用 GCD，只受**动画锁定**限制 |
| 插技 | Weaving | 在一个 GCD 技能之后、下一个 GCD 技能之前插入 oGCD |
| 单插 | Single weave | 插 1 个 oGCD |
| 双插 | Double weave | 插 2 个 oGCD |
| 三插 | Triple weave | 插 3 个 oGCD（通常需要极高延迟容忍，实战少见） |

**插技容量规则**（⚠️社区共识，见 [XIV Dev Wiki: Animation Lock](https://xiv.dev/game-internals/actions/animation-lock)）：

- 每个技能，无论 GCD 还是 oGCD，都会产生**动画锁定（Animation Lock）**，在锁定期间无法使用下一个技能。
- 动画锁定典型值约 **0.6 秒**（部分技能 0.7s 或更长，极限技/部分变身技可达 1.5s+）。❓具体数值随技能而异，社区常引用 0.6s 作为默认值。
- **双插可行性经验法则**：GCD ≥ 2.50s 时，双插几乎总是安全；GCD ≈ 2.40–2.45s 时双插开始有风险；GCD < 2.40s 时通常只能单插。
- 服务器存在**动作队列窗口**：在网络延迟正常时，提前约 **0.5 秒** 按下下一个技能会被缓冲执行（❓0.5s 为社区常引用的近似值）。

**为什么这很重要**：FF14 的高端循环设计几乎全部围绕「这个 GCD 里能塞几个 oGCD」展开。这也是「攻速并非越高越好」的原因——**攻速过快会挤压 oGCD 空间，导致爆发技能被推迟，反而降低总伤害**（社区称之为 "clipping" 与 "drift"）。

### 1.4 动画锁定的三种后果

| 现象 | 英文 | 成因 | 后果 |
|---|---|---|---|
| 卡刀 / 剪裁 | Clipping | 上一个技能动画锁定未结束就按下一个技能 | 下一个 GCD 整体后移，长期累积损失 |
| 漂移 | Drift | oGCD 因插不进去而被迫延后 | 爆发窗口与团队增益错位 |
| 丢帧执行失败 | — | 在锁定期间按键，指令被丢弃 | 技能未发动，直接损失 |

### 1.5 滑步（Slidecasting）

- **机制**：有施法时间的魔法，其施法条结束前存在一小段「安全移动窗口」。在此窗口内移动**不会**打断施法，角色会「滑」到新位置后完成施法。
- **窗口长度**：社区普遍引用为**最后约 0.5 秒**（❓部分资料表述为「最后 20% 施法时间」，两者在 2.5s 施法下近似）。
- 意义：这是**法系/治疗职业在不损失输出的情况下移动**的核心技巧。实战中大量机制处理都依赖滑步。
- ⚠️注意：滑步窗口的判定发生在**服务器端**，高延迟下实际可用窗口会缩短。

### 1.6 施法时间与瞬发

| 类型 | 说明 | 例子 |
|---|---|---|
| 有施法时间的魔法 | 需要读完施法条才发动，可被「移动」与「打断」中断 | 黑魔 Fire III、治疗 Raise |
| 瞬发（Instant） | 立即发动，可在移动中自由使用 | 大多数能力技、部分战技 |
| 由状态赋予瞬发 | 如黑魔「Firestarter」「Thunderhead」使后续法术瞬发 | ✅官方 Job Guide |
| 硬直（Root） | 少数技能在发动期间锁住角色位置 | 例：部分跳跃、突进技能 |

**施法时间同样受咏唱速度缩短**（⚠️社区：与 GCD 用同一 `f(速度)` 乘区），因此咏唱速度对法系是「双重收益」：既缩短 GCD，又缩短读条。

### 1.7 范围（AoE）形状

FF14 的攻击判定形状是**固定枚举**的，这对建模很关键——它不是任意多边形，而是少数几种参数化形状：

| 形状 | 英文 | 参数 | 典型代表 | 判定模型 |
|---|---|---|---|---|
| 圆形（以自身为中心） | Circle / Point-blank AoE | 半径 | 战士 Overpower、暗骑 Unleash | 目标与施法者距离 ≤ R |
| 圆形（指定地面） | Ground-targeted Circle | 半径 + 目标点 | 多数地面 AoE | 目标与落点距离 ≤ R |
| 圆形（以目标为中心） | Target-centered Circle | 半径 | 多数单体附带溅射技能 | 目标与主目标距离 ≤ R |
| 扇形 / 锥形 | Cone | 半径 + 角度 | 龙骑 Doom Spike 之外的多为直线；白魔 Assize 非扇形 | 距离 ≤ R 且夹角 ≤ θ/2 |
| 直线 / 矩形 | Line / Rect | 长度 + 宽度 | 龙骑 Doom Spike、机工 Gunbreaker 类直线 | 投影到轴向的距离与横向偏移 |
| 环形 / 甜甜圈 | Donut | 外半径 + 内半径 | 部分 BOSS 技能 | R_inner ≤ d ≤ R_outer |
| 十字 / 环形衍伸 | Cross, Line-stack | — | 部分 BOSS 技能 | ❓ |

⚠️社区补充规则：
- **绝大多数 AoE 有目标上限（damage falloff）**：超过一定敌人数量后，后续目标受到的伤害按比例衰减（常见为「第 N 个之后减伤 X%」）。这是 FF14 与多数 MMO 不同的设计点。❓具体系数逐技能不同（✅技能提示会写明）。
- 玩家 AoE 技能的伤害不随命中目标数减少，但**部分技能**有上限（如 5 目标后衰减）。✅技能提示可查。

### 1.8 复活与削弱

| 状态 | 英文 | 效果 | 持续时间 | 可信度 |
|---|---|---|---|---|
| 战斗不能 | KO | 无法行动，需要被复活或返回 | — | ✅官方 |
| 衰弱 | **Weakness** | 降低 HP、造成伤害、治疗量（社区常引用为 **−25%**） | 100 秒 | ⚠️官方有过提示文本，具体数值请以当前版本提示为准 |
| 濒死 | **Brink of Death** | 更强的削弱（社区常引用为 **−50%**） | 100 秒 | ⚠️/❓ |
| 复活硬直 | — | 被复活后短时间内无法再被同一效果立即复活 | — | ❓ |

**复活手段**（✅官方 Job Guide）：
- 治疗职业：白魔 **Raise**、学者 **Resurrection**、占星 **Ascend**、贤者 **Egeiro**
- 召唤师 **Resurrection**（复活的召唤兽技能）、赤魔 **Verraise**（有连续复活能力）
- 部分 PvP / 特殊内容有专用复活机制

**限制**（副本设计侧）：
- 部分高难副本设有**复活次数限制**或**禁止复活**（如「绝」系列、深层迷宫、部分单人挑战）。
- 复活后仍带衰弱，导致被复活的 DPS 需要数十秒才能恢复到正常输出——这是**「死亡惩罚」的主要形式，而不是掉落物品**。✅官方设计（副本无死亡掉物）。

## 2. 属性系统：主属性与副属性

### 2.0 术语对照（⚠️本节非常重要，中文译名存在两套体系）

FF14 国服官方译名与社区（Allagan Studies 中文译本 / NGA）译名不一致，做数值文档时必须先对齐：

### 2.2 HP 与 MP 公式

⚠️社区推导（[Allagan Studies 中文文档](https://ff14.17173.com/content/2021-05-03/20210503135838090.shtml)，Lv80 版本）：

```
HP(非T) = ⌊ Level{Lv}{HP} × Job{Job}{HP} / 100 ⌋ + ⌊ (VIT − Level{Lv}{MAIN}) × 22.1 ⌋
HP(T)   = ⌊ Level{Lv}{HP} × Job{Job}{HP} / 100 ⌋ + ⌊ (VIT − Level{Lv}{MAIN}) × 31.5 ⌋
```

| 项目 | Lv80 值 | 说明 |
|---|---|---|
| 每点体质 → HP（非 T） | 22.1 | ⚠️社区，Lv80 实测 |
| 每点体质 → HP（T） | 31.5 | ⚠️社区，源于防护精通特性 |
| 每点信仰 → 每跳 MP | `⌊150 × (PIE − MAIN) / DIV⌋` | Lv80 DIV = 3300；Lv100 用 2780 后为 `⌊150 × ESI / 2780⌋` |
| MP 每跳基础值 | 200 | 每 3 秒一跳（战斗状态） |
| MP 上限 | 10000 | ✅官方 |
| 技能回 MP | `⌊ 技能威力 × 10000 / 1000 ⌋` | 例：醒梦（威力 500）→ 恢复 5000 MP |

> ❓Lv100 的每点体质 HP 系数未在本次调研中取得权威数值。推测略高于 Lv80（等级越高系数越大），**建模时建议按 Lv80 值并留出 ±20% 调整空间**。

### 2.3 副属性：完整作用表

| 副属性 | 作用 | 生效范围 | 是否影响治疗 | 可信度 |
|---|---|---|---|---|
| **暴击 Critical Hit** | 提升暴击**发生率**，**同时**提升暴击**伤害倍率** | 全部伤害与治疗 | ✅是（治疗也能暴击） | ✅官方（机制）/ ⚠️公式 |
| **意志力 Determination** | 稳定提升**所有伤害与治疗量** | 全部伤害与治疗 | ✅是 | ✅官方 |
| **直击 Direct Hit** | 提升**直击发生率**；直击伤害 ×1.25 | **仅伤害** | ❌否（治疗不能直击） | ✅官方（机制）/ ⚠️倍率 |
| **技能速度 Skill Speed** | 缩短战技复唱 + 提升 DoT/自动攻击伤害 | 物理武器技能、DoT、AA | ❌ | ✅官方 |
| **咏唱速度 Spell Speed** | 缩短魔法复唱与读条 + 提升 DoT/自动攻击伤害 | 魔法、DoT、AA | ❌ | ✅官方 |
| **坚韧 Tenacity** | 提升造成伤害、提升受到治疗、降低受到伤害 | **仅防护职业** | ✅（提升自我治疗） | ✅官方（仅 T）/ ⚠️公式 |
| **信仰 Piety** | 提升 MP 自然回复 | **仅治疗职业** | — | ✅官方 |

**关键设计洞察**：
1. **暴击是「双重收益」属性**——同一个数值同时加暴击率和暴击倍率（两者增量完全相同，见 §3.5）。这让暴击在多数 build 中拥有最高的边际收益。
2. **直击只加率不加倍率**（倍率恒为 1.25），且不受暴击影响之外的其他修正。它每点「更便宜」（50.5 点 = 1%），但天花板低。
3. **信念 / 意志力是唯一「无上限无条件」的乘区**——它同时增幅伤害与治疗，对治疗职业的期望价值高于其面板 DPS 表现。
4. **坚韧是 T 专属的「攻防一体」属性**，但因系数最差（24.82 点 = 0.1% 伤害），历史上长期被视为**最弱副属性**；只有在需要减伤的极限进度场景才有价值。

### 2.4 属性的「零基准值」与收益曲线

**关键概念**：副属性的收益**不是从 0 开始算的**，而是从「零基准值（zero-base）」开始。

| 属性类别 | Lv 100 零基准值 | 说明 |
|---|---|---|
| 暴击 / 直击 / 技能速度 / 咏唱速度 / 坚韧 | **420** | ⚠️社区（[Flyxiv](https://junyeopn.github.io/blog/docs/ffxivtheory/)） |
| 主属性 / 意志力 / 信仰 | **440** | ⚠️社区（同上） |

```
有效属性增量 ESI(Stat) = Stat − ZeroBase(Stat)
```

**为什么重要**：所有副属性公式本质上都是 `FLOOR(系数 × ESI / 2780)`。这意味着：
- 属性 < 零基准值时，该副属性**完全无效**（甚至显示为负，公式取整后归零）。
- 每一点的**绝对收益是线性的**，但因为公式取整（0.1% 一档），实际收益呈**阶梯状（tier）**——这就是 FF14 社区所谓的 **「属性阈值（stat tier）」**。
- 例子：直击从 420 → 470 提升 1.0%（471 前无变化），从 470 → 471 **立即多 0.1%**。**配装的本质是「凑到刚好跨过阈值」，多余的点数是浪费的。**

### 2.5 伤害属性收益的近似换算（Lv 100）

**换算率 → 每 100 点属性的期望 DPS 收益**（由 §3 的公式直接推算，⚠️社区推导）：

| 副属性 | 每 100 点的期望 DPS 收益 | 曲线形状 | 备注 |
|---|---|---|---|
| **暴击** | **约 +0.43%**（低暴击时）→ **约 +0.59%**（高暴击时） | **边际递增**（凸） | 双重收益（率 + 倍率）→ 堆越高越强 |
| **直击** | **约 +0.49%**（恒定） | 线性 | 与意志力几乎完全等价 |
| **意志力** | **约 +0.50%**（恒定） | 线性 | 同时增幅治疗 → 对治疗职业价值更高 |
| **技能速度 / 咏唱速度** | **约 +0.47%**（仅 DoT / 自动攻击部分）**+ GCD 阈值跳变** | 线性 + 阶跃 | 实际收益高度依赖「能否多塞一个 GCD」与 oGCD 空间 |
| **坚韧** | **约 +0.40%**（伤害，仅 T） | 线性 | 系数最差；另有独立的减伤收益 |

**换算率对照**（每 1% 需要多少点）：

| 副属性 | 每 +0.1% 需要 | 每 +1% 需要 |
|---|---|---|
| 暴击（率 & 倍率同步） | 13.9 点 | 139 点 |
| 直击（率） | 5.055 点 | 50.5 点 |
| 意志力（伤害） | 19.86 点 | 198.6 点 |
| 坚韧（伤害） | 24.82 点 | 248.2 点 |
| 坚韧（减伤） | 13.9 点 | 139 点 |
| 技能速度 / 咏唱速度 | 21.38 点 | 213.8 点 |

> ⭐**关键结论（出乎直觉，但很重要）**：**在 Lv 100 的换算率下，「暴击 / 直击 / 意志力」三者每 100 点的期望收益几乎完全相同（0.43%–0.59%）**。这正是社区所说「クリ・ダイレクトヒット・意思力はほぼ同等」的原因（⚠️[来源](https://jp.finalfantasyxiv.com/lodestone/character/19859416/blog/5241984)：7.2 起「21–22 点副属性 ≈ +0.1% 期望伤害」）。
>
> 因此 FF14 的配装选择**不是**「哪个属性数值上更强」，而是：
> 1. **暴击在总量高时反超** → 堆暴击的 build 会在后期更强（凸性）；
> 2. **意志力同时增幅治疗** → 治疗职业优先；
> 3. **直击最「便宜」（50.5 点 / 1%）** → 属性点被取整浪费的风险最小；
> 4. **速度有阈值** → 跨过阈值时收益突变，是「配装艺术」的主要来源。
>
> ❓上表为**基于社区公式的直接推算，非实测**。精确的边际收益需要通过模拟器（XIVSim、Akhmorning 的 DPS 表、The Balance 的配装表）逐 build 计算。**做放置游戏时不要照抄，只需保留「暴击双重收益且凸、直击/意志力线性、速度有阈值」这三个定性结论。**

## 3. ⭐ 伤害计算公式（最重要）

> ### ⚠️⚠️ 免责声明

> 主要来源：
> - [Allagan Studies（前 Theoryjerks）](https://www.akhmorning.com/allagan-studies/) —— 社区最权威的数值研究组织
> - [さらちゃんのつぶやき：伤害计算公式详解（含完整算例）](https://sarachantubuyaki.jp/column/detailed-explanation-of-damage-calculation-formula)
> - [如何成为光之数学家 第3版（中文转载）](https://ff14.17173.com/content/2021-05-03/20210503135838090.shtml)
> - [Flyxiv FFXIV Stat Theory (7.0 Dawntrail)](https://junyeopn.github.io/blog/docs/ffxivtheory/)
> - [JP Lodestone：黄金（7.05）技能/咏唱速度计算](https://jp.finalfantasyxiv.com/lodestone/character/42324892/blog/5438925)
>
> 这些公式**在当前版本（7.56）的精度约为 ±1%，但从未被官方确认**。使用于游戏设计时请视为「量级正确的参考模型」。

### 3.1 总体结构（四段式）

社区模型把一次伤害拆成 **D1 → D2 → D3 → D** 四个阶段，每阶段做一次向下取整（floor）：

```
D1 = ⌊ ⌊ Potency × f(ATK) × f(DET) ⌋ / 100 ⌋ / 1000 ⌋
D2 = ⌊ ⌊ ⌊ D1 × f(TNC) ⌋ / 1000 ⌋ × f(WD) ⌋ / 100 ⌋ × Trait ⌋ / 100 ⌋
D3 = ⌊ D2 × ( f(CRIT) × critRate/100000 + (1 − critRate/100) ) ⌋
        × ( f(DH) × dhRate/100000 + (1 − dhRate/100) ) ⌋
D  = ⌊ ⌊ D3 × rand[95,105] ⌋ / 100 ⌋ × buff₁ ⌋ × buff₂ ⌋ ...
```

**乘区语义（这是本节最重要的一张表）**：

| 阶段 | 包含的乘区 | 性质 |
|---|---|---|
| **D1** | 效力 Potency、攻击力 f(ATK)、意志力 f(DET) | 角色「面板强度」 |
| **D2** | 坚韧 f(TNC)、武器性能 f(WD)、职业特性 Trait | 装备与职业修正 |
| **D3** | 暴击期望、直击期望 | 随机属性期望 |
| **D** | 伤害浮动 rand[95,105]%、所有增伤 Buff | 外部修正，**全部乘算** |

> ⚠️**重点结论**：`buff` 之间是**乘法叠加**的（`×buff₁ ×buff₂`），不是加法。这与很多手游的「增伤加算」设计不同，直接决定了 FF14 的团辅堆叠收益极高。

### 3.2 各函数定义（⚠️社区推导）

**通用记号**：`MAIN` = 主属性零基准值，`SUB` = 副属性零基准值，`DIV` = 等级除数，`JobAttribute` = 职业系数。

| 等级 | MAIN | SUB | DIV | 来源 |
|---|---|---|---|---|
| Lv 70 | 292 | 292 | 900 | [JP Lodestone](https://jp.finalfantasyxiv.com/lodestone/character/42324892/blog/5438925) |
| Lv 80 | 340 | 380 | 1300（❓另一来源给 3300） | 同上 / [AS 中译](https://ff14.17173.com/content/2021-05-03/20210503135838090.shtml) |
| **Lv 90** | **390** | **400** | **1900** | [さらちゃん完整算例](https://sarachantubuyaki.jp/column/detailed-explanation-of-damage-calculation-formula) 反推验证 |
| **Lv 100** | **440** | **420** | **2780** | [Flyxiv](https://junyeopn.github.io/blog/docs/ffxivtheory/) + [JP Lodestone](https://jp.finalfantasyxiv.com/lodestone/character/42324892/blog/5438925) |

**（1）攻击力函数 f(ATK)** —— 主属性的核心乘区

```
f(ATK) = ⌊ 195 × ( ATK − MAIN ) / MAIN ⌋ + 100      （Lv 90，非坦克）
       = ⌊ 0.5 × ( ATK − MAIN ) ⌋ + 100             （Lv 90–100，非坦克）
坦克：
f(ATK) = ⌊ 0.4 × ( ATK − MAIN ) ⌋ + 100             （Lv 90–100，防护职业）
```

| 版本 | 非坦克系数 | 坦克系数 | 备注 |
|---|---|---|---|
| Lv 80 | `⌊165 × (ATK−340)/340⌋ + 100` | `⌊115 × (ATK−340)/340⌋ + 100` | ⚠️ |
| Lv 90 | `⌊195 × (ATK−390)/390⌋ + 100` = 0.5/点 | ❓0.4/点（对应 ≈156/390） | ⚠️ |
| Lv 100 | `⌊0.5 × (ATK−440)⌋ + 100` | `⌊0.4 × (ATK−440)⌋ + 100` | ⚠️[Flyxiv](https://junyeopn.github.io/blog/docs/ffxivtheory/) |

> **重要**：`ATK` 对物理职业 = 物理攻击力（Attack Power），对法系 = 攻击魔法威力（Attack Magic Potency），对治疗输出 = 治疗魔法威力（Healing Magic Potency）。三者都由对应的主属性按等级表换算（见 §2.1）。
> **主属性收益是「线性」的**：主属性每多 1 点，f(ATK) 就多约 0.5（非坦克）——注意这里是**绝对增量恒定**，因此主属性的**百分比收益随主属性总量递减**（边际收益递减）。

**（2）意志力函数 f(DET)**

```
f(DET) = ⌊ 140 × ( DET − MAIN ) / DIV + 1000 ⌋
```
- Lv 90：`⌊140 × (DET − 390)/1900 + 1000⌋` → 0.1% 每 13.57 点
- Lv 100：`⌊140 × (DET − 440)/2780 + 1000⌋` → 0.1% 每 19.86 点 ⚠️[Flyxiv](https://junyeopn.github.io/blog/docs/ffxivtheory/)
- 5.x（Lv80）版本系数为 **130**，DIV 见上表。

**（3）坚韧函数 f(TNC)** —— 仅防护职业

```
f(TNC) = ⌊ 110 × ( TNC − SUB ) / DIV + 1000 ⌋   （Lv 90，攻击加成）
f(TNC) = ⌊ 112 × ( TNC − SUB ) / DIV + 1000 ⌋   （Lv 100，攻击加成）
减伤侧：
f(TNC_mit) = ⌊ 200 × ( TNC − SUB ) / DIV + 1000 ⌋ （Lv 100，0.1% 每 13.9 点）
```

**（4）武器性能函数 f(WD)** —— 武器伤害的核心

```
f(WD) = ⌊ ( MAIN × JobAttribute / 1000 ) + WD ⌋
```
- `WD` = 武器的**物理基本性能**或**魔法基本性能**（面板可见值）。
- `JobAttribute` = 职业系数（⚠️来自 Allagan Studies 的 Modifiers 表）。Lv90 的已知值：**治疗职业 = 115**，其余职业 ❓（多数约 100，坦克约 110）。
- Lv 90 治疗示例：`⌊(390 × 115 / 1000) + 126⌋ = ⌊44.85 + 126⌋ = 170`
- **解读**：`MAIN × JobAttribute / 1000` 这一项本质上是「等级带来的固定武器性能补偿」，在同等级同职业下是常数。它可以被理解为 **「每个等级给所有武器加的一个固定底数」**。

> ⭐ **设计启示**：这是 FF14 把「等级成长」与「装备成长」解耦的关键设计。武器性能的**线性加成**使得「换一把武器」的收益非常直观（例如 WD 从 126 → 130 相当于 +2.3% × (170/126)…实际上因为常数项存在，实际收益约 +2%）。

**（5）职业特性 Trait**

- 治疗职业在 Lv40 获得「アクションダメージ・回復量アップII（Maim and Mend II）」类特性，**伤害与治疗 ×1.30**（⚠️[さらちゃん](https://sarachantubuyaki.jp/column/detailed-explanation-of-damage-calculation-formula)）。
- 其他职业各有自己的增伤特性，社区模型统一用 `Trait` 一个整数乘区表示（单位：百分之一，如 130 = ×1.30）。
- ❓各职业的 Trait 具体数值本次未逐一核实；**建模时可视为「职业基础倍率」**。

### 3.3 完整算例（Lv 90，治疗职业，社区方法复现）⚠️

输入（[来源算例](https://sarachantubuyaki.jp/column/detailed-explanation-of-damage-calculation-formula)）：

| 项目 | 值 |
|---|---|
| 技能 | フォールマレフィク（贤者），效力 **250** |
| 攻击魔法威力 ATK | 2940（= 意念 MND） |
| 意志力 DET | 1788 |
| 坚韧 TNC | 400（= 零基准，无加成） |
| 武器基本魔法性能 WD | 126 |
| JobAttribute | 115（治疗） |
| 特性 Trait | 1.30 |
| 暴击 CRIT | 2257 |
| 直击 DH | 544 |

**逐步计算**：

```
f(ATK) = ⌊195 × (2940 − 390)/390⌋ + 100 = ⌊1275⌋ + 100 = 1375
f(DET) = ⌊140 × (1788 − 390)/1900 + 1000⌋ = ⌊1103.01⌋ = 1103
f(TNC) = 1000
f(WD)  = ⌊(390 × 115/1000) + 126⌋ = ⌊170.85⌋ = 170
f(CRIT)     = ⌊200 × (2257 − 400)/1900 + 1400⌋ = 1595   → 暴击倍率 159.5%
critRate    = ⌊200 × (2257 − 400)/1900 + 50⌋/10 = 24.5%
f(DH)       = 1250                                       → 直击倍率 125.0%（固定）
dhRate      = ⌊550 × (544 − 400)/1900⌋/10 = 4.1%

D1 = ⌊ ⌊ 250 × 1375 × 1103 ⌋ / 100 ⌋ / 1000 ⌋
   = ⌊ 379156250 / 100 ⌋ / 1000 ⌋ = ⌊ 3791562.5 / 1000 ⌋ = 3791
D2 = ⌊ ⌊ ⌊ D1 × f(TNC) ⌋ / 1000 ⌋ × f(WD) ⌋ / 100 ⌋ × Trait ⌋ / 100 ⌋
   = ⌊ ⌊ ⌊ 3791 × 1000 ⌋ / 1000 ⌋ × 170 ⌋ / 100 ⌋ × 130 ⌋ / 100 ⌋
   = ⌊ ⌊ 3791 × 170 ⌋ / 100 ⌋ × 130 ⌋ / 100 ⌋
   = ⌊ 6444 × 130 ⌋ / 100 ⌋ = ⌊ 837720 / 100 ⌋ = 8377
     → 不计暴击/直击：8377 ± 5%
D3 = ⌊ D2 × ( f(CRIT)×p_crit/100000 + (1 − p_crit/100) )
          × ( f(DH)  ×p_dh  /100000 + (1 − p_dh  /100) ) ⌋
   = ⌊ 8377 × (1595 × 24.5/100000 + (1 − 0.245))
            × (1250 × 4.1/100000 + (1 − 0.041)) ⌋
   = ⌊ 8377 × 1.145775 × 1.01025 ⌋ = 9696
     → 计入暴击/直击期望：9696 ± 5%
D  = ⌊ 9696 × 1.06 × 1.06 ⌋ = 10894   （叠加两个 +6% 增伤 Buff）
     → 单次命中期望值 = 10894 ± 5%
```

### 3.4 暴击（Critical Hit）

**双公式（Lv 100）** ⚠️[Flyxiv](https://junyeopn.github.io/blog/docs/ffxivtheory/)：

```
暴击率（%）       = 5% + ⌊ 200 × ESI(CRIT) / 2780 ⌋ / 10      -- ESI = CRIT − 420
暴击伤害倍率（%） = 140% + ⌊ 200 × ESI(CRIT) / 2780 ⌋ / 10
                    ↑ 同一个增量同时加在「率」和「倍率」上
```

| 概念 | 数值 | 可信度 |
|---|---|---|
| 零暴击属性时的基础暴击率 | **5%** | ⚠️社区 |
| 零暴击属性时的暴击倍率 | **1.40×**（+40%） | ⚠️社区（与 5.x `f(CRIT)` 在 CRIT=SUB 时 = 1400 一致） |
| 每点暴击对暴击率的贡献 | 0.1% / 13.9 点 | ⚠️社区 |
| 每点暴击对暴击倍率的贡献 | 0.1% / 13.9 点（**与率完全同步**） | ⚠️社区 |
| 暴击对治疗的适用 | ✅**治疗也可以暴击**，倍率同伤害 | ✅官方机制 |

**直觉理解**：暴击属性每跨过 139 点，同时获得 +1% 暴击率 **和** +1% 暴击倍率。这导致暴击的期望收益是**二次型**：

```
期望暴击收益倍率 = 1 + p × (m − 1)
其中 p = 暴击率, m = 暴击倍率
因为 p 与 m 同步增长 → 收益随暴击属性超线性增长
```

**示例（Lv 100）**：

| 暴击属性 | ESI | 暴击率 | 暴击倍率 | 期望收益倍率 | 相对基础提升 |
|---|---|---|---|---|---|
| 420 | 0 | 5.0% | 140.0% | 1.0200 | — |
| 700 | 280 | 7.0% | 142.0% | 1.0294 | +0.92% |
| 1000 | 580 | 9.1% | 144.1% | 1.0401 | +2.0% |
| 2000 | 1580 | 16.3% | 151.3% | 1.0836 | +6.2% |
| 3000 | 2580 | 23.5% | 158.5% | 1.1370 | +11.5% |
| 3500 | 3080 | 27.1% | 162.1% | 1.1683 | +14.5% |

> 上表按公式手算，取整误差 ±0.1%。**结论：暴击在 3000+ 之后仍有加速的边际收益，因此 FF14 的 BiS 配装几乎总是「暴击堆满」。**

### 3.5 直击（Direct Hit）

```
直击率（%） = ⌊ 550 × ESI(DH) / 2780 ⌋ / 10     -- ESI = DH − 420
直击伤害倍率 = 125.0% （固定，不随属性变化）
```

| 项目 | 数值 | 可信度 |
|---|---|---|
| 基础直击率（属性 = 420） | **0%** | ⚠️社区 |
| 每点直击 → 直击率 | 0.1% / 5.05 点 | ⚠️社区 |
| 直击伤害倍率 | **×1.25**（固定） | ⚠️社区共识（[AS 中译](https://ff14.17173.com/content/2021-05-03/20210503135838090.shtml) 明确写 +25%） |
| 直击是否影响治疗 | ❌**不影响**（治疗只会暴击，不会直击） | ✅官方机制 |

**示例**：

| 直击属性 | ESI | 直击率 | 期望收益倍率 |
|---|---|---|---|
| 420 | 0 | 0.0% | 1.0000 |
| 500 | 80 | 1.5% | 1.0038 |
| 700 | 280 | 5.5% | 1.0138 |
| 1000 | 580 | 11.4% | 1.0287 |
| 1500 | 1080 | 21.3% | 1.0534 |
| 2000 | 1580 | 31.3% | 1.0783 |
| 2500 | 2080 | 41.1% | 1.1029 |

**直击的边际收益是纯线性的**：每 5.05 点 = 0.1% 概率 = 0.0125% 期望伤害。这就是社区常说的「直击便宜但上限低」。

### 3.6 暴击与直击的叠加规则

⚠️社区模型：

```
暴击 + 直击同时发生时：伤害 = 基础伤害 × 暴击倍率 × 1.25
（乘法叠加，不是加法）
```

在期望值模型中（§3.1 的 D3），两者被写成**相互独立的两个期望乘区**：

```
临界乘区期望 = f(CRIT)×p_crit/100000 + (1 − p_crit/100)     -- 单位：倍率
直击乘区期望 = f(DH)  ×p_dh  /100000 + (1 − p_dh  /100)
```

| 情形 | 倍率（基础暴击 140%、直击 125%） |
|---|---|
| 普通命中 | ×1.000 |
| 仅直击 | ×1.250 |
| 仅暴击（140%） | ×1.400 |
| 暴击 + 直击 | ×1.750（= 1.400 × 1.250） |

> ❓**不确定点**：有少数资料声称暴击与直击是**加法**叠加（1 + 0.40 + 0.25 = 1.65）。但 [さらちゃん](https://sarachantubuyaki.jp/column/detailed-explanation-of-damage-calculation-formula) 的算例明确使用乘法形式，且社区主流模拟器（XIVSim 等）也使用乘法。**本文件采用乘法，标注为 ⚠️社区主流但未官方确认。**

### 3.7 伤害浮动范围

```
rand[95, 105]  →  最终伤害在「计算值 × 0.95」到「计算值 × 1.05」之间均匀分布
```

| 项目 | 数值 | 可信度 |
|---|---|---|
| 浮动范围 | **±5%**（0.95 – 1.05） | ⚠️社区（公式中明确写为 rand[95,105]） |
| 分布 | ❓推测为**均匀分布**，但对数正态也有可能 | ❓未证实 |
| 浮动施加位置 | 在暴击/直击之后、Buff 之前（D3 → D） | ⚠️社区 |
| 治疗量是否有浮动 | ❓治疗量浮动范围可能更小（部分资料称治疗无浮动或 ±3%） | ❓不确定 |

> ⭐**设计启示**：FF14 的单次伤害浮动只有 ±5%，非常**窄**。这与「抽卡式大浮动」的设计理念不同——FF14 的随机性几乎全部集中在**暴击/直击的二元判定**上，而不是伤害数值的分布。放置游戏若追求「FF14 手感」，应该用**低数值浮动 + 高概率型随机（暴击/直击）**，而不是高方差。

### 3.8 Buff / 增伤乘区的叠加

⚠️社区：**所有「造成伤害提高 X%」的 Buff 之间是乘法叠加。**

| 叠加方式 | 例子 | 结果 |
|---|---|---|
| 乘算 | +6% 与 +6% | ×1.06 × 1.06 = ×1.1236（不是 ×1.12） |
| 与暴击/直击的关系 | 暴击倍率与增伤 Buff | 乘算 |
| 与减伤的关系 | 见 §4.3 | 通常乘算 |

**两个 +6% 不是 +12%，而是 +12.36%**。当团辅数量增加时，乘法叠加会导致爆发窗口内的伤害**指数式膨胀**——这正是 FF14「2 分钟爆发元」能够成立、也让平衡变得极其困难的数学根源（见 §7）。

## 4. 效力、治疗、护盾、减伤与仇恨

### 4.1 效力（Potency）机制

**定义**：效力是 FF14 用来标定技能强弱的**无量纲归一化数值**。✅官方会在每个技能的提示中直接给出效力数值（例如「威力：250」）。

| 概念 | 说明 | 可信度 |
|---|---|---|
| 基准 100 效力 | 相当于一次「基准攻击」的量级 | ⚠️社区共识 |
| 效力与现实伤害的关系 | `现实伤害 ∝ 效力 × f(ATK) × f(DET) × f(WD) × ...`（见 §3） | ⚠️社区 |
| 跨职业技能比较 | **不能直接比较**——不同职业的 `JobAttribute`、`Trait`、主属性总量不同 | ⚠️社区 |
| 效力 vs 时间 | 真正的 DPS 指标是 **PPS（Potency Per Second）= 效力 / 复唱时间** | ⚠️社区 |

**关键性质**：

1. **效力是乘区而非加区**：效力在公式最内层作为乘数，所以「效力 +10%」和「伤害 +10%」等价（在不考虑取整时）。
2. **效力受攻速影响**：因为攻速缩短复唱，单位时间内的效力总和上升 → 攻速的收益本质是「PPS 提升」。
3. **合力（Combos）**：连击的后续技能通常有更高的效力（如 200 → 300 → 400），因此**断连击 = 效力损失**。
4. **AoE 效力与目标数**：多数 AoE 技能对每个目标都用同一效力，但**部分技能有目标上限衰减**（✅技能提示会写明，例如「超过 2 个目标时威力降低」）。

**社区常用的派生指标**：

| 缩写 | 全称 | 含义 |
|---|---|---|
| **pPS / PPS** | Potency Per Second | 效力 / 复唱时间，衡量技能效率 |
| **aDPS** | Adjusted DPS | 剔除团队增益后的个人 DPS |
| **rDPS** | Raid DPS | 把团队增益的贡献归给施放者后的 DPS |
| **nDPS** | Neutral DPS | 完全剔除所有外部增益的 DPS |
| **CDPS** | — | rDPS + 部分无法归因的修正（已废弃） |

> ⚠️上表为社区（FF Logs）定义，非官方。**对放置游戏而言，只需理解「效力 = 技能基础强度系数，PPS = 效力 / 冷却」这一层。**

### 4.2 治疗量公式（⚠️社区推导）

治疗使用与伤害**相同的骨架**，但有三处关键差异：

| 差异 | 伤害 | 治疗 |
|---|---|---|
| 使用的「攻击力」 | 物理攻击力 / 攻击魔法威力 | **治疗魔法威力**（由意念 MND 推导） |
| 直击 | ✅适用 | ❌**不适用**（治疗不能直击） |
| 暴击 | ✅适用 | ✅适用（治疗可以暴击，倍率公式相同） |
| 伤害浮动 | ±5% | ❓疑似**无浮动**（待核实） |

**治疗公式（社区结构）**：

```
H1 = ⌊ ⌊ Potency × f(治疗魔法威力) × f(DET) ⌋ / 100 ⌋ / 1000 ⌋
H2 = ⌊ ⌊ ⌊ H1 × f(TNC) ⌋ / 1000 ⌋ × f(WD) ⌋ / 100 ⌋ × Trait ⌋ / 100 ⌋
H  = ⌊ H2 × 治疗增幅Buff ⌋          （暴击时再 × f(CRIT)/1000）
```

| 项目 | 说明 | 可信度 |
|---|---|---|
| 治疗也受意志力 DET 影响 | ✅官方（意志力说明含「恢复量」） | ✅官方 |
| 治疗也受坚韧 TNC 影响 | ✅官方（仅 T 自身受到的治疗？❓是「T 造成的治疗」还是「T 受到的治疗」需区分） | ❓ |
| 治疗暴击基础倍率 | 1.40×（与伤害同公式） | ⚠️社区 |
| 治疗是否受「治疗魔法效果提高」Buff | ✅官方，乘算 | ✅官方 |
| 治疗是否有 ±5% 浮动 | ❓未确认，多数社区资料认为治疗**无浮动** | ❓ |

> ⭐**设计启示**：FF14 的治疗量**不随目标血量变化**（没有「残血加疗」机制），也没有「过量治疗惩罚」。治疗压力完全来自**伤害预测的准确度**与**MP/资源管理**。

### 4.3 护盾与减伤：乘算 vs 加算

#### 减伤（Mitigation）

**核心规则**：**不同来源的减伤效果之间是乘法叠加的**（⚠️社区共识，但被广泛验证，实际游戏内表现一致）。

```
实际受到伤害 = 原始伤害 × (1 − m₁) × (1 − m₂) × (1 − m₃) × ...
```

**示例**：

| 减伤组合 | 加法直觉 | 实际乘法结果 |
|---|---|---|
| 10% + 20% | 30% | **28%**（1 − 0.9×0.8 = 0.28） |
| 10% + 20% + 30% | 60% | **49.6%**（1 − 0.9×0.8×0.7 = 0.496） |
| 20% + 20% + 20% | 60% | **48.8%** |

**重要细节**：

| 规则 | 说明 | 可信度 |
|---|---|---|
| 同名 Buff 不叠加 | 同名的减伤 Buff 只刷新持续时间，**不叠加效果** | ✅官方机制 |
| 异名 Buff 叠加 | 不同名的减伤各自乘算 | ⚠️社区 |
| 无敌类效果 | 骑士 Hallowed Ground、战士 Holmgang、暗骑 Living Dead、绝枪 Superbolide 是**例外**（免疫 / 特殊机制），不是普通减伤 | ✅官方 |
| 减伤与护盾的关系 | **先算护盾，还是先算减伤？** ❓社区普遍认为是「先减伤，再扣护盾」（即护盾吸收的是减伤后的伤害） | ❓不确定 |
| 目标上限 | 减伤百分比是否有硬上限（如 90%）？❓ | ❓ |

#### 护盾（Shields）

| 规则 | 说明 | 可信度 |
|---|---|---|
| 护盾值计算 | 用治疗公式计算一个**固定数值**，作为伤害吸收池 | ⚠️社区 |
| 同类护盾叠加 | 不同来源的护盾**数值相加**（学者 Adloquium + 白魔 Divine Benison 等可共存） | ✅官方机制（可同时存在） |
| 护盾上限 | ❓是否能超过最大 HP 存在争议；社区一般认为护盾总量可超过 HP 但超出部分浪费 | ❓ |
| 护盾持续时间 | 各自独立 | ✅官方 |
| 护盾与「减伤」的等价性 | 从**减伤总量**角度，护盾与百分比减伤在数学上不等价（护盾是固定值，减伤是比例） | — |

> ⭐**设计建议**：护盾与百分比减伤在数值建模上是**两种不同性质的防御资源**：
> - **百分比减伤**：对「大伤害」价值线性，对「小伤害」可能溢出浪费。
> - **固定值护盾**：对「高频小伤害」价值高，对「一次大伤害」价值有限。
> 一个好的放置游戏数值模型应该**同时保留两者**，让玩家在不同敌人面前做取舍。

### 4.4 仇恨（Enmity / Threat）机制

| 机制 | 说明 | 可信度 |
|---|---|---|
| 仇恨条 | 队友列表中每人有一个仇恨条/排名，✅官方即使在今天也存在 | ✅官方 |
| 仇恨生成 | 造成伤害 / 治疗会生成仇恨，数值与伤害/治疗量成正比 | ✅官方 |
| 治疗仇恨 | 治疗生成的仇恨通常为**治疗量的一半**（社区常引用的系数） | ⚠️社区 |
| **坦克姿态（Tank Stance）** | 骑士 Iron Will / 战士 Defiance / 暗骑 Grit / 绝枪 Royal Guard：**仇恨生成 ×10** | ⚠️官方技能提示有「大幅提高仇恨」，具体倍率社区常引用 10× |
| 挑衅 Provoke | 把自己在目标仇恨列表中的位置**提升到第一位**（并略微超过当前第一） | ⚠️官方提示 + 社区细节 |
| 转移 Shirk | 把自己当前仇恨的 **25%** 转移给指定队友 | ⚠️社区（官方提示：转移大量仇恨） |
| 仇恨衰减 | ❓FF14 中**没有**仇恨随时间衰减的机制（与 WoW 不同） | ❓ |
| 现版本地位 | 自 5.0 起，仇恨管理在普通内容中**几乎被简化到不存在**；只在零式/绝本的 **Tank Swap（换T）** 场景才重要 | ⚠️社区共识 |

> ⭐**设计启示**：现代 FF14 的仇恨系统是**「几乎无重的机制」**——除非做换 T 机制。对放置游戏而言，仇恨系统通常应简化或省略；如果要做，就做成「T 拉住 BOSS、其他人自由输出」的二值开关，而不是复杂的仇恨数值竞速。

### 4.5 DoT（持续伤害）与自动攻击

#### DoT

⚠️社区推导：DoT 使用与直伤几乎相同的公式，但**用速度函数 f(SPD) 替代部分乘区**：

```
D1 = ⌊ ⌊ Potency × f(ATK) × f(DET) ⌋ / 100 ⌋ / 1000 ⌋
D2 = ⌊ ⌊ ⌊ D1 × f(TNC) ⌋ / 1000 ⌋ × f(SPD) ⌋ / 1000 ⌋ × f(WD) ⌋ / 100 ⌋ × Trait ⌋ / 100 ⌋
f(SPD) = ⌊ 130 × ( Speed − SUB ) / DIV + 1000 ⌋
```

| 规则 | 说明 | 可信度 |
|---|---|---|
| DoT 跳数间隔 | **每 3 秒一跳** | ✅官方（游戏内提示/Debuff 显示） |
| DoT 是否受益于速度 | ✅是（提速会提升每跳伤害） | ⚠️社区 |
| **快照（Snapshot）** | DoT 在**施加瞬间**锁定施法者的属性与 Buff，之后即使 buff 消失伤害也不变 | ⚠️社区共识（这也是「爆发窗口内先铺 DoT」的原因） |
| DoT 是否暴击 | ✅可以暴击/直击（每跳独立判定） | ⚠️社区 |
| DoT 是否受目标减伤影响 | ✅受 | ✅官方 |
| 同源 DoT 覆盖 | 同一技能重复施加会**刷新**而不是叠加 | ✅官方机制 |

#### 自动攻击（Auto-Attack）

```
f(平A) = ⌊ ( ⌊ MAIN × JobAttribute / 1000 ⌋ + WD ) × ( 攻击间隔 / 3 ) ⌋
```

| 项目 | 说明 | 可信度 |
|---|---|---|
| 攻击间隔 | 由武器决定（面板可见），例如 2.64s、3.04s、3.20s 等 | ✅官方 |
| 受益于速度 | ✅技能速度/咏唱速度会缩短自动攻击间隔 | ⚠️社区 |
| 法系是否有自动攻击 | 有，但伤害极低（且占星等职业使用隐藏的**物理**基本性能） | ⚠️[AS 中译](https://ff14.17173.com/content/2021-05-03/20210503135838090.shtml) |
| 对 DPS 的贡献 | 近战/坦克约 5%–10% 的总伤害 | ⚠️社区经验值 |

## 5. 物品等级、食物与药水

### 5.1 物品等级（iLvl）与属性预算

**基本规则**（✅官方）：

- 每件装备有 **物品等级（Item Level, iLvl）**，iLvl 决定该装备能提供的属性**总预算**。
- 装备的**主属性、体质、副属性**都来自这个预算；武器另有独立的**武器基本性能（Weapon Damage, WD）**。
- 穿戴不低于当前等级的装备是进入副本的门槛条件（iLvl 限制）。

**iLvl 与数值成长的社区经验规律**（⚠️[Sarimile Fon 的实测近似](https://jp.finalfantasyxiv.com/lodestone/character/19859416/blog/5241984)，Dawntrail 7.x）：

| 关系 | 数值（Lv 100 / IL 740–765） | 旧版本参考（6.4 时代） |
|---|---|---|
| **武器基本性能 WD** 成长 | 每 **5 iLvl → +1 WD**（近年长期维持该节奏） | 同 |
| **+1 WD 的火力收益** | **约 +0.50%** | 约 +0.60%–0.61% |
| **+10 主属性的火力收益** | 约 +0.19%（= 1 点 ≈ +0.019%） | 约 +0.36%–0.37% |
| **+15 副属性的火力收益** | 约 +0.07%（7.2 起为 **21–22 点 ≈ +0.1%**） | 约 +0.1% |
| **1 WD ≈ 多少主属性** | **约 25–26 点主属性** | ❓ |

> ⭐**这个「1 WD ≈ 25 主属性」的比值是 FF14 装备成长设计的核心锚点**：它解释了为什么「武器升级」永远是版本内最大的单件收益。

### 5.2 具体装备升级案例（⚠️[实测数据](https://jp.finalfantasyxiv.com/lodestone/character/19859416/blog/5241984)）

| 升级 | 主属性变化 | 副属性变化 | WD 变化 | 总火力变化 |
|---|---|---|---|---|
| 武器 IL745 → IL765（零式武器） | +74（+1.4–1.5%） | +30（+0.14%） | 148 → 152（+2.0%） | **+3.6% ~ +3.7%** |
| 饰品 IL740（新式满镶嵌）→ IL750（点数饰品） | +17（+0.35%） | −47（−0.21%） | — | +0.13% ~ +0.14% |
| 头/手/脚 IL740 → IL750 | +21（+0.43%） | −82（−0.37%） | — | +0.05% ~ +0.06% |
| 身/腿 IL740 → IL750 | +35（+0.72%） | −76（−0.35%） | — | +0.37% |

> ⭐⭐**极其重要的设计洞察**：上表第 2、3 行显示，**更高 iLvl 的装备并不总是更强**——因为高 iLvl 装备的副属性分配可能比「满禁忌镶嵌的制作装」更差。制作装（HQ + 打满）在版本中期经常**优于**更高 iLvl 的点数装备。
> **这意味着 FF14 的装备系统不是纯粹「iLvl 越大越好」的线性阶梯，而是「主属性 vs 副属性」的取舍问题。** 这是放置游戏数值设计可以借鉴的重要非线性来源。

### 5.3 主属性 : 副属性的等价值比例

按上面「1 主属性 ≈ +0.019%，1 副属性 ≈ +0.0045%」估算，两者**等价值比约为 1 : 4**。社区实测：

| 阶段 | 主属性总量 | 副属性总量（单属性） | 等价比例（主:副） |
|---|---|---|---|
| IL 730 | ≈ 4900 | ≈ 2300（意志力） | **3 : 14** |
| IL 760 | 更高 | — | **3 : 12** |
| 规律 | 版本后期主属性相对贬值，但每级装备的绝对增幅变大 | | ⚠️社区 |

### 5.4 团队加成（Party Bonus）

✅官方机制 / ⚠️数值：

| 规则 | 数值 |
|---|---|
| 队伍中包含 **坦克 / 治疗 / 近战 / 远程物理 / 法系** 五种职能时 | 每种职能提供 **STR/DEX/VIT/INT/MND +1%** |
| 主属性 +1% 对应的火力收益 | **约 +1.05%** |
| 满编 8 人（覆盖全部 5 种职能） | 主属性 +5% → 火力约 +5.25% |

> ⭐**设计启示**：这是「阵容多样性奖励」的经典实现——不是「同职业越多越强」，而是「职能越全越强」。放置游戏可直接借用：**队伍职能覆盖度 → 全队属性加成**。

### 5.5 食物（Food / Meal）

| 规则 | 数值 | 可信度 |
|---|---|---|
| 持续时间（NQ） | **30 分钟** | ✅官方 |
| 持续时间（HQ） | **40 分钟** | ✅官方 |
| 效果形式 | 文字显示为「**+X%（上限 Y）**」 | ✅官方 |
| 实际计算 | `加成 = min( 属性值 × X%, Y )` —— **乘算 + 硬上限** | ⚠️社区（[AS 属性公式](https://ff14.17173.com/content/2021-05-03/20210503135838090.shtml) 中食物为乘区） |
| 提供属性条数 | 通常 **2 条**（例如：主属性 + 体质，或 两个副属性） | ✅官方 |
| 上限 Y 的大小 | 由食物本身的等级/iLvl 决定（越高级的食物上限越高） | ✅官方 |
| 重复吃食物 | 新的食物效果**覆盖**旧效果，不叠加 | ✅官方机制 |
| 优先级 | 玩家通常选择「副属性食物」（如 暴击 + 直击）而非「主属性食物」，因为副属性食物在阈值配装下收益更高 | ⚠️社区 |

**食物加成的关键性质**：因为是「百分比 + 上限」，所以：
- 当你的属性很高时，**上限 Y 先到，实际加成变成固定值** → 食物收益随属性增长而**递减**（相对收益）。
- 这就是为什么「食物上限值」是版本更替时需要重新评估的关键数字。

### 5.6 药水（Tincture / 强化药）

| 规则 | 数值 | 可信度 |
|---|---|---|
| 效果 | 提升 **主属性**（力量/敏捷/智力/意念）X%（上限 Y） | ✅官方 |
| 持续时间 | **30 秒** | ✅官方 |
| 复唱时间 | **4 分 30 秒（270 秒）** | ✅官方 |
| NQ / HQ 差异 | HQ 版本的上限值更高 | ✅官方 |
| 典型用法 | 每场战斗使用 **1–3 次**，且**必定对齐爆发窗口** | ⚠️社区 |
| 与食物的叠加 | **叠加**（不同来源、不同状态） | ✅官方机制 |

> ⭐**设计启示**：药水是 FF14 中**唯一一个「主动 + 短时 + 长冷却」的爆发道具**。它的设计模式是：
> - 效果窗口（30s）< 冷却（270s），所以需要**择时**
> - 效果窗口与团队爆发窗口（120s）**对齐**时收益最大
> **放置游戏可以直接照搬这个结构：「有限次数 + 短窗口 + 需对齐」的爆发道具。**

## 6. 魔晶石（Materia）：镶嵌与上限

### 6.1 魔晶石类型

| 大类 | 具体类型 | 可镶嵌对象 |
|---|---|---|
| **战斗魔晶石（副属性）** | 暴击、直击、意志力、技能速度、咏唱速度、坚韧、信仰 | 战斗装备 |
| **战斗魔晶石（主属性）** | 力量、敏捷、体质、智力、意念 | ❓存在但**通常不可镶嵌进普通装备**（当年被官方限制，玩家实际只用副属性魔晶石）——**此项不确定，建议以当前游戏内提示为准** |
| **生产魔晶石** | 制作力、加工精度、CP | 生产职业装备 |
| **采集魔晶石** | 采掘力、鉴别力、GP | 采集职业装备 |
| **特殊** | 各类「XX之魔晶石」（如 Heavens' Eye 等，用于特定系统） | ❓ |

### 6.2 阶级（Grade）

| 阶级 | 引入版本 | 对应装备 iLvl 门槛 |
|---|---|---|
| I – V | 2.x（重生之境） | 低 |
| VI | 3.x–4.x | 中 |
| VII | 4.x（红莲之狂潮） | 高 |
| VIII | 5.x（漆黑之反逆者） | 更高 |

### 6.3 镶嵌（Melding）与禁忌镶嵌（Overmelding）

| 概念 | 英文 | 说明 | 可信度 |
|---|---|---|---|
| 安全槽 | Guaranteed slots | 装备自带 1–2 个绿色圆槽，镶嵌 **100% 成功** | ✅官方 |
| 禁忌镶嵌 | Advanced / Forbidden Melding | 在安全槽之外**额外**镶嵌，需要习得「禁忌镶嵌」技能 | ✅官方 |
| 可禁忌镶嵌的装备 | — | 主要是 **HQ 制作装备**；副本/点数装备通常**不可**禁忌镶嵌 | ✅官方 |
| 单件装备魔晶石上限 | — | **最多 5 个**（2 安全 + 3 禁忌，❓或 1+4，视装备而定） | ⚠️ |
| HQ 装备加成 | — | 对 HQ 装备进行禁忌镶嵌时，成功率**略高**（历史上约 +4~5 个百分点） | ⚠️ |
| 失败后果 | — | 魔晶石**被消耗**，装备不损坏 | ✅官方 |

**禁忌镶嵌成功率**：

| 槽位 | ARR 时代实测（Grade I–III，iLvl 50–55 装备）⚠️ | 现版本 |
|---|---|---|
| 第 1 次禁忌（NQ / HQ） | Tier I: 40% / 45%｜Tier II: 36% / 41%｜Tier III: 30% / 35% | ❓ |
| 第 2 次禁忌 | Tier I: 20% / 24%｜Tier II: 18% / 22%｜Tier III: 15% / 19% | ❓ |
| 第 3 次禁忌 | Tier I: 10% / 14%｜Tier II: 9% / 13%｜Tier III: 8% / 11% | ❓ |
| 第 4 次禁忌 | Tier I: 5% / 8%｜Tier II: 5% / 8%｜Tier III: 4% / 7% | ❓ |

> 上表来源：[Lodestone FC 论坛「Materia Melding Percentages」实测贴](https://na.finalfantasyxiv.com/lodestone/freecompany/9236179148295110686/forum/40936/)。
> ❓**重要不确定点**：该实测数据来自 **ARR 时代（等级上限 50）**，**不能直接用于当前版本**。现版本的成功率由「魔晶石阶级 vs 装备 iLvl」的匹配度决定，本文档**未能取得当前版本的权威成功率表**。
> **建模时建议**：只保留「安全槽 100% / 禁忌槽成功率逐槽递减且整体很低（末槽量级 5%–20%）」这一定性结构。

### 6.4 属性上限（Stat Cap）与「打满」

| 概念 | 说明 | 可信度 |
|---|---|---|
| **属性上限** | 每件装备对**每个副属性**都有一个上限值，由装备 iLvl 决定 | ✅官方机制 |
| 超过上限的部分 | **完全无效**（镶嵌了但不提供属性） | ✅官方 |
| 「打满 / Pentameld」 | 指把一件装备的 5 个槽都镶上魔晶石，并把关键副属性**堆到上限** | ⚠️社区术语 |
| 为什么需要「禁忌镶嵌」 | 装备自带的副属性通常**远低于上限**，需要靠魔晶石补足到上限 | ⚠️社区 |
| 上限的意义 | 防止玩家把某一属性堆到极端，同时给「配装」制造约束（这是 FF14 配装深度的来源） | ⚠️设计解读 |

> ⭐**设计启示**：**「属性上限（cap）+ 禁忌镶嵌」是 FF14 最有特色的装备机制之一。**
> 它的作用不是「让玩家变强」，而是：
> 1. **把「无脑堆一个属性」变成不可能**，强制玩家在多个副属性间做取舍；
> 2. **制造「够用就好」的边际**——超过上限的投入**收益恰为零**，形成一个非常清晰的「停止点」；
> 3. **为不同 iLvl 的装备制造非线性**（低 iLvl 满镶嵌 vs 高 iLvl 未打满）。
>
> 放置游戏若想复刻这种「配装乐趣」，可以设计 **`每件装备每属性 cap` + `可额外插槽`** 的组合。

### 6.5 魔晶石的获取与消耗

| 途径 | 说明 |
|---|---|
| 精气（Spiritbond）100% 后精制 | ✅官方：装备使用度满后可提取魔晶石 |
| 副本/任务掉落 | ✅官方 |
| 市场交易（Board） | ✅官方 |
| 分解（Desynthesis） | ✅官方，生产职业技能 |
| 需求量 | 一件满禁忌镶嵌的制作装，期望消耗**数十颗**同阶级魔晶石 ⚠️（因为失败会消耗） |

## 7. Buff/Debuff 与 2 分钟爆发元

### 7.1 Buff / Debuff 功能分类

FF14 的状态效果（Status）按功能可分为以下几类。**这个分类体系对放置游戏设计非常有用**，因为它天然对应「状态机的不同乘区」。

| 类别 | 英文 | 作用 | 典型例子 | 可信度 |
|---|---|---|---|---|
| **伤害提升** | Damage Dealt Up | 提升造成的伤害 | 战士 Storm's Eye、诗人的战斗之声（Battle Voice 提升直击/暴击） | ✅官方 |
| **属性提升** | Primary Stat Up | 提升 STR/DEX/INT/MND | 各类团辅（Divination、Battle Litany 等实质是暴击率） | ✅官方 |
| **暴击提升** | Critical Hit Rate Up | 提升暴击率（部分同时提升暴击伤害） | 战斗连祷 Battle Litany（+暴击率） | ✅官方 |
| **直击提升** | Direct Hit Rate Up | 提升直击率 | 战斗之声 Battle Voice | ✅官方 |
| **加速** | Haste / Speed Up | 缩短 GCD 与复唱 | 各类加速 Buff | ✅官方 |
| **减伤** | Damage Taken Down | 百分比降低受到的伤害 | 各类团减（Reprisal、Feint、Addle、Dismantle 等） | ✅官方 |
| **护盾** | Barrier | 提供固定值伤害吸收池 | 学者 Adloquium、白魔 Divine Benison | ✅官方 |
| **持续回复** | Regen / HoT | 每跳恢复 HP | 白魔 Regen、学者 Whispering Dawn | ✅官方 |
| **治疗增幅** | Healing Up / Healing Received Up | 提升治疗量或受到的治疗量 | 学者 Fey Illumination | ✅官方 |
| **无敌** | Invulnerability | 免疫伤害 | 骑士 Hallowed Ground、战士 Holmgang、暗骑 Living Dead、绝枪 Superbolide | ✅官方 |
| **状态免疫 / 净化** | Status Cleanse | 移除可净化状态 | 治疗职业 Esuna | ✅官方 |
| **变身 / 特殊资源** | Stance / Charge / Gauge | 进入特殊状态或获得充能 | 各职业技能 | ✅官方 |

**Debuff 分类**：

| 类别 | 英文 | 作用 | 典型 | 可信度 |
|---|---|---|---|---|
| **持续伤害** | Damage over Time (DoT) | 每 3 秒一跳伤害 | 各类 DoT 技能 | ✅官方 |
| **受伤增加** | Vulnerability Up / Damage Taken Up | 百分比增加受到的伤害 | 副本机制的「易伤」层数 | ✅官方 |
| **伤害降低** | Damage Down | 降低玩家造成的伤害（惩罚型） | 机制失误惩罚 | ✅官方 |
| **属性降低** | Stat Down | 降低 STR/DEX/INT/MND | 各类 Debuff | ✅官方 |
| **行动限制** | Heavy / Bind / Slow / Stun / Silence / Sleep / Paralysis / Pacification | 减速 / 定身 / 沉默 / 眩晕等 | 各类 BOSS 技能 | ✅官方 |
| **强制死亡计时** | Doom | 倒计时结束即死，需满足条件解除 | 常见于高难副本 | ✅官方 |
| **标记 / 点名** | Marker / Prey | 被指定为某种机制的目标 | 各类机制 | ⚠️社区术语 |

### 7.2 叠加与互斥规则

| 规则 | 说明 | 可信度 |
|---|---|---|
| **同名状态** | **不叠加**，只刷新持续时间（或取更强的效果覆盖弱的） | ✅官方机制 |
| **异名状态** | 可同时存在，效果**全部生效** | ✅官方机制 |
| **同类型的多个减伤** | 异名时**乘算**叠加（见 §4.3） | ⚠️社区 |
| **同类型的属性降低 Debuff** | 通常**互斥**（只生效最强的一个） | ⚠️社区 |
| **DoT** | 不同技能来源的 DoT **可共存**；同一技能重复施加**刷新** | ✅官方 |
| **食物** | 新食物**覆盖**旧食物 | ✅官方 |
| **药水** | 与食物独立，可叠加 | ✅官方 |
| **团队增益（Raid Buff）** | 不同职业的团辅可共存；同名不叠加 | ✅官方机制 |
| **属性提升类团辅（乘法叠加）** | 多个「伤害 +X%」之间是**乘法**（见 §3.8） | ⚠️社区 |
| **无敌类** | 通常互斥或无法同时生效 | ❓ |

> ⭐**设计启示**：FF14 的叠加规则可以总结成一句话：
> **「同名刷新，异名共存，效果乘算」**。
> 这三条规则简洁、可预测、且能产生丰富的组合空间。**建议放置游戏直接采用这一体系**，而不是设计复杂的「叠加上限 / 递减」规则。

### 7.3 「2 分钟爆发元」（The Two-Minute Meta）

#### 定义

**2 分钟爆发元**是指：自《漆黑之反逆者》（5.0）后期起、并在《晓月之终途》（6.0）中完成的**团队增益标准化**，导致几乎所有队伍的爆发窗口都自然对齐到同一个 **120 秒周期**。

#### 由来（时间线）

| 版本 | 状态 | 说明 |
|---|---|---|
| 2.x – 3.x | 团辅冷却混杂 | 各种 90s / 120s / 150s / 180s 的团辅，队伍需要复杂的对齐技巧 |
| 4.x 红莲之狂潮 | 混乱加剧 | 更多职业与团辅，对齐难度达到顶峰 |
| **5.0 漆黑之反逆者** | 开始标准化 | SE 开始把团辅统一往 120s 靠拢 |
| **6.0 晓月之终途** | **完成统一** | 绝大多数团队增益统一为 **120 秒复唱 / 约 20 秒持续**；个人爆发也统一到 60/120 秒 |
| 6.1 – 7.x | 2 分钟元固化 | 循环设计、配装、攻略全部围绕 120 秒轴展开 |
| **8.0 Evercold（2027-01）** | **媒体报道将终结**（详见 §7.4） | ⚠️媒体信息 |

#### 为什么形成

数学上的原因是 **§3.8 的乘法叠加**：

```
爆发窗口伤害 = 基础伤害 × ∏(1 + buffᵢ)
```

如果各团辅的冷却不一致（例如 90s / 120s / 180s），它们只在很长的时间尺度上偶发重合，**平均值较低**。而一旦全部统一到 120s，**每次爆发窗口都能吃到全部团辅的乘积**，团队 DPS 最大化。

**这就形成了一个纳什均衡**：任何一个职业如果把团辅改成 90s，反而会失去与其他团辅的重合，队伍总伤害下降 → 于是所有职业都向 120s 收敛。

#### 社区对 2 分钟元的批评（⚠️社区观点，非官方）

| 批评 | 说明 |
|---|---|
| 循环僵化 | 所有职业的循环都变成「2 分钟为一轮」，缺少个性 |
| 惩罚放大 | 在爆发窗口死亡/失误的代价极高 |
| 延迟敏感 | 团辅对齐要求队伍同步，对高延迟玩家不友好 |
| 乘法爆炸 | 团辅越多，爆发窗口的伤害膨胀越夸张，平衡难度指数上升 |
| 抹平差异 | 职业特色被「能否对齐 2 分钟」这一条标准统一 |
| 工具依赖 | 队伍大量依赖第三方工具（ACT/触发器）来对齐时间轴 |

## 9. ⭐ 面向放置游戏的数值模型建议（设计建议）

> **本章全部内容为「设计建议」，不是 FF14 事实。** 其中引用的 FF14 数值均来自前 8 章（并保留其可信度标注）。
> 目标：把 FF14 的 **GCD / 循环 / 团辅 / 爆发窗口** 抽象成适合放置游戏的 **DPS 系数 + 时间轴倍率** 模型。

### 9.0 三条设计原则

| 原则 | 说明 |
|---|---|
| **保留「手感」，舍弃「操作」** | 放置游戏的玩家不做按钮序列，但**应当感受到** FF14 的节律：稳定的 GCD 节拍、周期性的爆发高潮、暴击的惊喜、配装的取舍。 |
| **线性底层 + 乘法顶层** | FF14 的成长（主属性、WD、副属性）**几乎全是线性的**，而「爆发窗口」通过乘法叠加制造局部指数。**这个「线性底盘 + 乘法脉冲」的结构是 FF14 数值手感的核心，强烈建议照搬。** |
| **让每个数字都可解释** | FF14 的取整链条（floor × floor × floor）不适合放置游戏。**建议在 UI 上暴露化简后的乘区列表**（例如「主属性 ×14.8」「武器 ×1.9」「暴击期望 ×1.14」「爆发 ×1.46」），让玩家能看见自己的成长来自哪里。 |

### 9.1 层 1：单次命中公式（放置化版本）

**设计建议草案**：把 FF14 的四段式取整公式（§3.1）改写为**浮点乘法 + 展示层取整**。

```
H(P) = (P / 100)                    ① 效力
     × M_main                       ② 主属性乘区
     × M_weapon                     ③ 武器乘区
     × M_det                        ④ 意志力乘区
     × M_ten                        ⑤ 坚韧乘区（仅 T）
     × M_trait                      ⑥ 职业特性乘区
     × E_crit                       ⑦ 暴击期望
     × E_dh                         ⑧ 直击期望
     × R                            ⑨ 伤害浮动
     × ∏(1 + B_i · active_i)         ⑩ 增伤 Buff（乘算）
```

**各乘区的取值公式（对齐 FF14 Lv 100 的社区模型）**：

| 乘区 | 公式 | FF14 参考值 | 可信度 |
|---|---|---|---|
| ① 效力 | `P = 效力 / 100` | 技能面板效力 | ✅官方 |
| ② 主属性 | `M_main = [ (Main − 440) × A / 440 + 100 ] / 100`，`A = 237`（非T）/ `190`（T） | Lv100 实测 | ⚠️社区 |
| ③ 武器 | `M_weapon = (WD + JobConst) / 100`，`JobConst ≈ 44–50` | Lv100 实测 | ⚠️社区 |
| ④ 意志力 | `M_det = [ 140 × (Det − 440) / 2780 + 1000 ] / 1000` | 0.1% / 19.86 点 | ⚠️社区 |
| ⑤ 坚韧 | `M_ten = [ 112 × (Ten − 420) / 2780 + 1000 ] / 1000` | 0.1% / 24.8 点 | ⚠️社区 |
| ⑥ 职业特性 | 常数（治疗 ≈ 1.30） | 职业不同 | ⚠️社区 |
| ⑦ 暴击期望 | `E_crit = 1 + p_c × (m_c − 1)`，`p_c = (5 + ⌊(Crit−420)/13.9⌋)/100`，`m_c = (140 + ⌊(Crit−420)/13.9⌋)/100` | 见 §3.4 | ⚠️社区 |
| ⑧ 直击期望 | `E_dh = 1 + p_d × 0.25`，`p_d = max(0, ⌊(DH−420)/5.055⌋)/100` | 见 §3.5 | ⚠️社区 |
| ⑨ 浮动 | `R ~ Uniform(0.95, 1.05)` | ±5% | ⚠️社区 |
| ⑩ Buff | `∏(1 + B_i)` **乘法叠加** | 见 §3.8 | ⚠️社区 |

**💡 化简建议**：把 ②③④⑤⑥ 合并成一个面板数值 **「攻击系数 ATK_COEF」**：

```
ATK_COEF = M_main × M_weapon × M_det × M_ten × M_trait
```
玩家面板只显示 `ATK_COEF`（例如 ×1583.4）。这样既保留了真实的乘区结构，又给玩家一个可比较的单一数字。

### 9.2 层 2：把「循环」抽象为 DPS 系数

#### 9.2.1 基础抽象

放置游戏中玩家不做按钮序列，因此**循环必须被压缩成常数**。建议定义：

| 符号 | 名称 | 定义 |
|---|---|---|
| `L` | **循环时长（Loop Length）** | 一个完整循环的自然时长（秒），由 GCD 与循环结构决定 |
| `P_GCD` | **循环内 GCD 效力总和** | Σ(所有 GCD 技能的效力) |
| `P_oGCD` | **循环内 oGCD 效力总和** | Σ(所有能力技的效力) |
| `N_oGCD` | 循环内 oGCD 数量 | 用于计算插技拥挤 |

**PPS（每秒效力）**：

```
PPS = ( P_GCD + P_oGCD × η_weave ) / L
```

其中 `η_weave` 是**插技效率**（oGCD 是否能全部塞进 GCD 间隙），取值：

| GCD | 允许的 oGCD 数 | η_weave 建议 |
|---|---|---|
| ≥ 2.50s | 2 | 1.00 |
| 2.40–2.49s | 1–2 | 0.85 |
| 2.30–2.39s | 1 | 0.70 |
| < 2.30s | 1（且易剪裁） | 0.55 |

> ⭐**这是最关键的抽象**：**攻速不是无条件收益**。当 GCD 太短时，oGCD 塞不进去 → `η_weave` 下降 → 总 DPS 反而降低。
> **放置游戏如果不做这个惩罚，攻速就会变成无脑最优属性，失去配装乐趣。强烈建议保留 η_weave 曲线。**

#### 9.2.2 从 PPS 到 DPS

```
DPS_base = PPS / 100 × H(1) 的乘区部分（不含浮动与临时 Buff）
```

即：

```
DPS_base = PPS/100 × M_main × M_weapon × M_det × M_ten × M_trait × E_crit × E_dh
```

**具体示例（建议的放置游戏初始值）**：

| 参数 | 值 |
|---|---|
| 循环时长 L | 120 秒 |
| GCD | 2.5s |
| 循环内 GCD 数 | 48 |
| GCD 效力总和 P_GCD | 48 × 320 = 15360 |
| oGCD 效力总和 P_oGCD | 4800 |
| η_weave | 1.00 |
| **PPS** | (15360 + 4800) / 120 = **168** |
| 主属性乘区 M_main | ×14.8 |
| 武器乘区 M_weapon | ×1.90 |
| 意志力乘区 M_det | ×1.10 |
| 职业特性 | ×1.30 |
| 暴击期望 E_crit | ×1.14 |
| 直击期望 E_dh | ×1.04 |
| **DPS_base**（相对指数） | 1.68 × 14.79 × 1.90 × 1.10 × 1.30 × 1.14 × 1.04 ≈ **80.1** |

> 注：`DPS_base` 是一个**相对指数**（无量纲），用于比较不同配装/成长的强度，不等于游戏内显示的伤害数字。放置游戏中建议再乘一个全局缩放常数，把指数映射到可读的伤害量级。

### 9.3 层 3：把「团辅」抽象为「爆发窗口倍率」

#### 9.3.1 核心公式

```
爆发窗口占比    w = T_window / T_period
对齐时的倍率    BurstMult_aligned = ∏(1 + b_i)
平均倍率        BurstMult_avg = 1 + (BurstMult_aligned − 1) × w
```

#### 9.3.2 「对齐 vs 不对齐」的价值量化（设计建议中最有价值的结论）

如果各团辅的窗口**不同步**（各自独立、随机分布），则期望倍率是：

```
BurstMult_random = ∏[ 1 + b_i × w_i ]
```

**数值示例**：4 个团辅，每个 `b = 10%`，`w = 20/120 = 1/6`

| 情形 | 计算 | 倍率 |
|---|---|---|
| **完美对齐**（2 分钟元） | `1.10⁴` | **1.4641** |
| **完全不对齐**（各自独立） | `(1 + 0.1/6)⁴ = 1.01667⁴` | **1.0685** |
| **对齐的价值** | 1.4641 / 1.0685 | **+37.0%** |

> ⭐⭐**这就是「2 分钟爆发元」能统治 FF14 的数学原因**：仅仅是把团辅同步，就能带来 **+37% 的团队伤害**。没有任何职业调整能抵消这么大的差距。
> **对放置游戏而言，这意味着：只要你的模型里有「乘法叠加的短窗口 Buff」，玩家就一定会自发追求对齐。** 你可以：
> - **利用它**：把「团辅对齐」做成一个可玩的核心系统（例如「同步率」指标）；
> - **或规避它**：把 Buff 做成加法叠加、或改为常驻光环。

#### 9.3.3 放置化的「爆发窗口」实现建议

| 设计方案 | 说明 | 适合 |
|---|---|---|
| **自动爆发（推荐）** | 系统自动把所有团辅对齐到同一个周期；玩家只调「周期长度」 | 轻度放置 |
| **可配置周期** | 每个团辅有独立 CD，玩家通过升级/装备调整 CD，追求对齐 | 中重度放置 |
| **同步率指标** | 面板显示「团辅同步率 = 对齐倍率 / 完美倍率」，作为可优化目标 | 提供成长感 |
| **爆发充能条** | 把「2 分钟」抽象成一条充能条，充满即进入爆发窗口 | 强表现力 |

**设计警告**：如果 Buff 周期固定为 120s，而战斗时长通常是 60–90s，那么爆发窗口的**相位**会变得重要（可能一次都触发不了）。建议：
- 或者在战斗开始时立即充满一次；
- 或者让周期随等级缩短；
- 或者引入「相位提前量」机制。

### 9.4 属性成长曲线设计建议

**FF14 的真实曲线**（⚠️社区）：伤害对主属性、WD、副属性**全部线性**。这意味着：

```
DPS ∝ (a × MainStat + b) × (c × WD + d) × (1 + e × Substat)
```

**线性成长的优缺点**：

| | 说明 |
|---|---|
| ✅ 优点 | 可预测、易平衡、不会数值爆炸、玩家的每一点投入都有稳定回报 |
| ❌ 缺点 | 缺少「爆炸感」；放置游戏玩家期待指数级成长 |

**建议的混合方案（设计建议）**：

| 层 | 曲线 | 作用 |
|---|---|---|
| **底层（属性 → 乘区）** | **线性**（照搬 FF14） | 稳定性、可预测性、便于做配装 |
| **中层（装备 iLvl → 属性）** | **线性** | 每个 iLvl 的收益恒定 |
| **顶层（转生/觉醒/层级）** | **指数**（例如 ×1.15 per level） | 提供放置游戏必需的「爆炸感」 |
| **脉冲层（爆发窗口）** | **乘法**（照搬 FF14） | 提供节律与高潮 |

> 这样设计的效果：**玩家在单次配装层面体验到 FF14 的「精打细算」，在长期成长层面体验到放置游戏的「指数快感」。**

### 9.5 完整的「放置化战斗数值模型」公式草案

```
═══════════ 输入 ═══════════
MainStat   主属性（力量/敏捷/智力/意念）
WD         武器性能
Crit, DH, Det, Spd, Ten   副属性
JobConst   职业常数（44–50）
A         主属性斜率（237 非T / 190 T）
Trait      职业特性乘区
PartyRoles 队伍职能覆盖数（0–5）
Buffs[]    buff 列表 {b_i, T_window_i, T_period_i}
Loop       循环定义 {L, P_GCD, P_oGCD, BaseGCD}
iLvlCaps   各副属性上限

═══════════ 派生 ═══════════
GCD        = BaseGCD × 1000 / ⌊130 × (Spd − 420)/2780 + 1000⌋
M_main     = ((MainStat − 440) × A / 440 + 100) / 100
M_weapon   = (WD + JobConst) / 100
M_det      = (140 × (Det − 440) / 2780 + 1000) / 1000
M_ten      = (112 × (Ten − 420) / 2780 + 1000) / 1000     [T only, else 1]
p_c        = (5 + ⌊(Crit − 420)/13.9⌋) / 100
m_c        = (140 + ⌊(Crit − 420)/13.9⌋) / 100
E_crit     = 1 + p_c × (m_c − 1)
p_d        = max(0, ⌊(DH − 420)/5.055⌋) / 100
E_dh       = 1 + p_d × 0.25
η_weave    = f(GCD)        // 见 §9.2.1 表
w_i        = T_window_i / T_period_i

═══════════ 计算 ═══════════
PPS        = (P_GCD + P_oGCD × η_weave) / L

ATK_COEF   = M_main × M_weapon × M_det × M_ten × Trait
            × E_crit × E_dh

DPS_base   = PPS / 100 × ATK_COEF

BurstAligned = ∏(1 + b_i)
BurstAvg     = 1 + (BurstAligned − 1) × mean(w_i)

PartyMult  = 1 + 0.01 × PartyRoles × 1.05      // 每职能 +1% 主属性 ≈ +1.05% 伤害
FoodMult   = (食物加成已并入属性，不单独乘)
PotionMult = 1 + 药水增益 × 药水窗口占比

DPS        = DPS_base × BurstAvg × PartyMult × PotionMult

═══════════ 离线结算 ═══════════
OfflineDamage = DPS × T_offline × η_offline
建议 η_offline ∈ [0.5, 0.8]（离线效率，作为付费/成长钩子）
```

### 9.7 「数值钩子」清单（玩家追求的目标）

放置游戏需要清晰的可追求目标。以下是从 FF14 机制中提炼出的、**天然产生「差一点就达成」张力**的钩子：

| # | 钩子 | 机制来源 | 张力来源 |
|---|---|---|---|
| 1 | **攻速阈值** | GCD 取整到 0.01s | 「再快 0.01 秒就能多打一发」 |
| 2 | **暴击 : 直击 最优比** | 暴击双重收益 vs 直击线性 | 「该堆哪个？」永不唯一解 |
| 3 | **副属性 cap（打满）** | 装备属性上限 | 「再镶一颗就满，但成功率只有 20%」 |
| 4 | **团辅同步率** | 乘法叠加的爆发窗口 | 「把 CD 调到 120 秒，伤害 +37%」 |
| 5 | **iLvl 台阶** | 每 5 iLvl = +1 WD | 「换武器 = +3.7% 总伤害」 |
| 6 | **主属性 : 副属性 配比** | IL730 时约 3:14 | 「这件装备主属性高但副属性差」 |
| 7 | **oGCD 拥挤** | 动画锁定 | 「攻速堆太多反而掉 DPS」 |
| 8 | **食物/药水的上限值** | 「+X%（上限 Y）」 | 「属性涨了，食物反而变弱了」 |
| 9 | **职能覆盖** | 队伍加成 +1%/职能 | 「再招一个法系就满加成」 |
| 10 | **死亡惩罚窗口** | Weakness 100 秒 | 「这次死亡让我们错过了 DPS check」 |

### 9.8 不建议照搬的部分

| FF14 机制 | 为什么不建议照搬 | 建议替代 |
|---|---|---|
| **四段式 floor 取整链** | 玩家完全无法理解；且在浮点环境里无意义 | 内部用 double，UI 层取整 |
| **主属性倍率高达 3000%+** | 数字过大，缺乏直觉 | 归一化到「×1.0 基准」的展示 |
| **仇恨系统** | 现代 FF14 中已基本退化为「T 拉住即可」 | 简化为二值开关或直接省略 |
| **身位（Positional）** | 依赖实时走位，放置游戏无法表达 | 抽象成「近战加成 ×1.05」的常驻系数 |
| **插技/动画锁定（精确到 0.1s）** | 需要毫秒级操作 | 抽象成 η_weave 效率曲线（§9.2.1） |
| **滑步** | 纯操作技巧 | 抽象成「移动惩罚减免」属性 |
| **DoT 快照机制** | 对玩家不可见，容易产生 bug 感 | 改为动态刷新，或明确展示「快照」规则 |

### 9.9 「FF14 手感」的最小可玩核心（MVP 建议）

如果要做一个「感觉像 FF14」的放置游戏，以下 6 个要素是**不可省略**的：

1. **GCD 节拍**：以 2.5s 为基准的离散时间轴（即使自动推进，也要让玩家看见「每 2.5 秒一次结算」）。
2. **效力系统**：每个技能有明确的效力数字，可比较、可优化。
3. **暴击的双重收益**：暴击同时加率与加倍率 → 让暴击成为「越堆越强」的属性。
4. **短窗口乘法团辅**：周期性的爆发窗口，且 Buff 乘算 → 制造高潮与对齐玩法。
5. **oGCD 拥挤惩罚**：攻速不是无条件最优 → 保留配装取舍。
6. **副属性 cap**：装备有「打满」的概念 → 制造明确的停止点与随机镶嵌的赌博感。

**这 6 条共同构成了 FF14 战斗数值的「指纹」。缺少任何一条，游戏就会变成另一个普通的数值游戏。**

1. **❓❓ 伤害公式的全部常数均未经官方确认。** 本文件提供的 Lv90/Lv100 常数来自多个社区来源的交叉验证，精度传闻为 ±1%，但**没有任何官方保证**。用于实际游戏设计时，请以「量级与结构正确」为标准，不要当作精确复刻。
2. **❓❓ Lv80 的等级除数存在来源冲突**：Allagan Studies 中译版给 `Level{80}{DIV} = 3300`，而 JP Lodestone 的实测推导给 Lv80 = 1300（与 Lv90=1900、Lv100=2780 形成单调序列）。**本文件采信 1300**，但保留疑问。
3. **❓ Lv100 主属性斜率存在两个版本**：[Flyxiv](https://junyeopn.github.io/blog/docs/ffxivtheory/) 给 0.5（非T）/ 0.4（T）；[Sarimile Fon](https://jp.finalfantasyxiv.com/lodestone/character/19859416/blog/5241984) 给 237/440 ≈ 0.5386（非T）/ 190/440 ≈ 0.4318（T）。**本文件以 Sarimile 的实测值为准（并在 §9 中使用），因为其给出了具体的装备升级验证数据。**
4. **❓ 暴击与直击是乘法叠加还是加法叠加**：本文件采用**乘法**（社区主流），但存在少数不同说法。
5. **❓ 当前版本的禁忌镶嵌成功率未取得**：仅有 ARR 时代的实测数据（§6.3）。
6. **❓ 7.56 版本的具体最大 iLvl 未核实**：本文件只给出「iLvl → 属性」的成长规律，未列具体数值表。
7. **❓ 治疗量是否有 ±5% 浮动**：未确认。
8. **❓ 护盾与减伤的计算顺序**（先减伤后扣盾，还是先扣盾后减伤）：未确认。
9. **❓ 8.0《Evercold》的全部信息均来自游戏媒体**，本文件未能核实 Square Enix 官方公告原文。特别是「Evolved 模式移除 2 分钟爆发元」这一条，**请以官方发布会/官方公告为准**。
10. **❓ 部分数值为社区经验值而非公式推导**（如「每点体质 = 22.1 HP」、「1 WD ≈ 25 主属性」等），仅供参考。

### 10.4 一句话总结

> **FF14 的伤害数值体系可以概括为：**
> **「线性底盘（主属性 / 武器 / 副属性）+ 二元随机（暴击 / 直击，±5% 浮动）+ 乘法爆发（短窗口团辅全部乘算）+ 阈值取整（属性阶梯 / 属性 cap）」**
>
> 其中前三项决定了它的**手感**，第四项决定了它的**配装深度**。
> 对放置游戏的移植，建议**保留全部四项结构**，但把「操作」换成「自动结算」，把「取整」藏到展示层之下。
